Recursive helpers that return a pointer

Each call returns the first node (list) or the root (tree) of its part of the structure after the change. The caller stores that pointer back into the link it came from. Most of the time it is the same pointer; once in a while it is not.

How to use this demo
  1. Pick an Operation, then click one of the buttons next to Try to load an example.
  2. Step through the trace with Next and Prev, or with the Left and Right arrow keys. Play runs the trace on its own; the slider sets the speed.
  3. Watch three things together:
    • Code: the highlighted line is the one running now
    • Call stack: one box per call; the top box is the call running now
    • Memory: the nodes and pointers; the #k badge marks the node p of call #k
  4. Each time a call returns, its pointer moves up to the link that stores it: gray means the same pointer is stored back and nothing changes; orange means the link really changes.
  5. Turn on Forget to store the result (bug) and run the same example again. You can see what goes wrong when the code ignores the returned pointer.
  6. Type your own keys in the input boxes and click Trace it.

Tip: before you click Next, predict what the current call will return and which link will change. Then check.
